# Разработка под Яндекс Игры

Практическая памятка для этого проекта. Полные требования лежат рядом:
[`YANDEX_GAMES_REQUIREMENTS.md`](YANDEX_GAMES_REQUIREMENTS.md).

Цель файла: чтобы обычные игровые изменения не ломали интеграцию с платформой
и не приводили к отклонению сборки на модерации.

## 1. Что уже подключено

- **SDK:** `Playgama Bridge for Godot 4`, версия `2.4.4`.
  Аддон лежит в `addons/playgama_bridge/`, автолоад `Bridge` стоит **первым**.
- **Экспорт Web:** кастомный HTML-shell
  `res://addons/playgama_bridge/template/index.html`,
  выходной файл — `index.html`.
- **Конфиг платформы:** `addons/playgama_bridge/template/playgama-bridge-config.json`.
  При экспорте Playgama-постпроцессор кладёт `playgama-bridge.js` и
  `playgama-bridge-config.json` рядом с `index.html`.
- **Готовность игры:** `PlatformIntegration.mark_game_ready()` вызывается после
  стартового запуска ракеты.
- **Геймплей:** `PlatformIntegration.gameplay_started()` /
  `gameplay_stopped()` вызываются из `assets/scripts/game.gd`.
- **Пауза:** только `PauseManager`. Платформенная пауза приходит в
  `PlatformIntegration._on_platform_pause_changed()`.
- **Звук:** шины `Music` и `SFX` в `default_bus_layout.tres`, управление — через
  автолоад `AudioSettings`.
- **Сохранения:** на вебе только `Bridge.storage`, на десктопе — `ConfigFile`.
  Владелец данных — автолоад `GameState`.
- **Реклама:** межстраничная реклама вызывается в естественной паузе через
  `PlatformIntegration.show_interstitial()`.

## 2. Железные правила

### 2.1. SDK и платформа

- Не вызывай `ysdk` и `playgama-bridge` напрямую из GDScript. Только через
  автолоады `Bridge` и `PlatformIntegration`.
- `Bridge` обязан оставаться **первым** автолоадом в `project.godot`.
  Если он окажется после `GameState`, чтение облака начнётся до инициализации
  SDK.
- Не убирай `[editor_plugins]` и `[audio]` из `project.godot`.
- Не меняй Web-экспорт обратно на `closedspace.html`: Яндекс требует
  `index.html` в корне архива.
- Не отключай кастомный HTML-shell: именно он инициализирует SDK до запуска
  Godot и подключает `playgama-bridge-config.json`.

### 2.2. Сохранения

- На вебе **нельзя** сохранять прогресс через `ConfigFile`, `FileAccess`,
  `localStorage` или cookies. Только `Bridge.storage`.
- Не создавай второй независимый сейв. Все игровые данные должны проходить
  через `GameState`.
- При добавлении нового поля прогресса обнови **все четыре места** в
  `assets/scripts/globals/game_state.gd`:
  1. переменную состояния;
  2. `_build_save_data()`;
  3. `_apply_save_data()`;
  4. `_load_local_save()` и `_save_local_save()` для десктопного `ConfigFile`.
- Если поле добавлено в облако, но не добавлено в `_apply_save_data()`, после
  перезапуска оно молча потеряется.
- Не сохраняй на каждую пулю/каждую монету синхронно. Используй
  `queue_save()`; при потере фокуса и закрытии игра делает `_flush_save()`.
- Не удаляй `GameState.loaded`. Оболочка `app_frame.gd` ждёт этот сигнал, чтобы
  не запустить игру с нулями до загрузки облака.
- `reset_save()` должен сохранять настройки звука. Если добавляешь новые
  настройки, реши, сбрасываются они или нет, и обнови функцию осознанно.
- Не меняй `STORAGE_KEY` без миграции: старый прогресс игроков останется по
  старому ключу.

### 2.3. Пауза и фокус

- Не вызывай `get_tree().paused = true/false` из игровых сцен. Только
  `PauseManager.pause()`, `resume()`, `abort()`, `reset()`,
  `slow_to_modal()`, `release_modal()`.
- Если добавляешь модальное окно, используй `PauseManager.modal_tween()`.
  Обычный `create_tween()` остановится на паузе.
- Экран, который должен ставиться на паузу при сворачивании, обязан быть в
  группе `PauseManager.FOCUS_PAUSE_GROUP`. Сейчас это делает `game.gd`.
- Не включай авто-возобновление после возврата фокуса. Игрок должен сам нажать
  «Продолжить», иначе он пропустит момент возобновления.
- Платформенная пауза (`pause_state_changed`) не должна ломать меню и магазин:
  `PauseManager.pause_for_platform()` уже проверяет наличие игровой сцены.

### 2.4. Музыка и звуки

- Музыка — только на шине `Music`. Игровые звуки — только на шине `SFX`.
- Не глуши `Master`: это выключит всё, включая будущие системные звуки, и
  усложнит диагностику.
- Для новых `AudioStreamPlayer` / `AudioStreamPlayer2D` явно указывай
  `bus = AudioSettings.MUSIC_BUS` или `AudioSettings.SFX_BUS`.
- Кнопки в паузе должны менять состояние через `AudioSettings`, а не напрямую
  через `AudioServer`. Тогда настройка сохранится в `GameState`.
- Платформенный запрет звука (`platform.is_audio_enabled` /
  `audio_state_changed`) — внешний. Не включай звук принудительно в обход него.
- Если добавляешь новый источник звука, проверь его в паузе: музыка должна
  продолжаться (или глушиться кнопкой), а игровые SFX — останавливаться вместе
  с деревом.

### 2.5. Локализация

- Все новые пользовательские строки добавляй в
  `assets/localization/en.csv` (колонки `keys,en,ru`).
- Не вставляй русский/английский текст прямо в `.tscn` или `.gd`, если это
  видимая игроку строка. Используй `tr("ключ")`.
- Английский — fallback. Русский обязателен, потому что аудитория Яндекса
  русскоязычная.
- Язык платформы применяется в `PlatformIntegration._apply_platform_language()`.
  Если добавляешь третий язык, обнови и этот метод, и `project.godot`.

### 2.6. Реклама и монетизация

- Не показывай рекламу по таймеру и не прерывай активный геймплей.
- Единственная допустимая точка сейчас — смерть забега, перед магазином:
  `PlatformIntegration.show_interstitial()` в `_on_rocket_died()`.
- Если добавляешь новую точку, сначала вызывай `gameplay_stopped()`, затем
  рекламу, и только после её закрытия продолжай игру.
- Не показывай рекламу, если `Bridge.advertisement.is_interstitial_supported`
  равно `false`; `PlatformIntegration` уже это проверяет.
- Rewarded-рекламу нельзя выдавать за обязательную награду. Сначала игрок
  должен явно согласиться.

### 2.7. Контент и UI

- Не оставляй в билде карточки/кнопки/экраны с текстом «прототип», «не
  реализовано», «TODO» и без эффекта. Сейчас это относится к карточке `laser`.
- Не добавляй функции, которые не работают на вебе или в мобильном браузере,
  без скрытия/замены.
- Интерфейс проектируется под 720×1280 (9:16). Не добавляй горизонтальный
  скролл страницы, контекстное меню и выделение текста.
- Не используй зарезервированные браузерные жесты и горячие клавиши.
- Проверяй, что кнопки не перекрываются в маленьком окне и в полноэкранном
  режиме.

### 2.8. Сеть, авторизация, платежи

- Не добавляй внешнюю авторизацию, сторонние API, аналитику и платежи без
  отдельного согласования с требованиями Яндекса.
- Если понадобятся покупки, использовать только модуль `Bridge.payments`, а не
  сторонние платёжные виджеты.
- Не добавляй ссылки на внешние сайты в игровом UI.

## 3. Чек-лист перед каждым изменением

- [ ] Новая строка добавлена в `en.csv` и вызывается через `tr()`.
- [ ] Новый звук назначен на `Music` или `SFX`.
- [ ] Новое поле прогресса добавлено во все точки сохранения/загрузки.
- [ ] Новый экран не ломает `PauseManager` и не вызывает `get_tree().paused`.
- [ ] Новая кнопка в паузе не перекрывает существующие и работает на телефоне.
- [ ] Новый контент действительно работает, а не является заглушкой.
- [ ] На вебе не появилось прямое использование `ConfigFile`/`localStorage`.
- [ ] Реклама не появляется во время активного геймплея.
- [ ] После изменения `project.godot` автолоад `Bridge` всё ещё первый.

## 4. Чек-лист перед релизом

1. Открыть проект в Godot и убедиться, что плагин `playgama_bridge` включён.
2. Экспортировать Web в пустую папку.
3. Проверить, что в корне экспорта есть:
   - `index.html`;
   - `index.js`;
   - `index.wasm`;
   - `index.pck`;
   - `playgama-bridge.js`;
   - `playgama-bridge-config.json`.
4. Убедиться, что `index.html` — это Playgama-shell, а не стандартный Godot-shell.
5. Загрузить папку в тестовый черновик Яндекс Игр (sandbox), пройти загрузку,
   старт, паузу, смерть, магазин, покупку улучшения, перезапуск.
6. Проверить в браузере:
   - звук включается/выключается кнопками;
   - сворачивание вкладки ставит игру на паузу;
   - после возврата игра не возобновляется сама;
   - прогресс сохраняется после перезагрузки страницы;
   - язык интерфейса соответствует языку платформы.
7. Проверить размер архива: должен быть меньше 100 МБ.
8. Проверить, что в архиве нет тестовых сцен/скриптов, если они не нужны в
   релизе.
9. Проверить отсутствие текста «прототип» и неработающих кнопок.
10. Проверить права на спрайты, музыку и SFX; добавить файл credits/LICENSE,
    если его ещё нет.

## 5. Как добавлять типовые вещи

### Новое поле прогресса

1. Добавить переменную в `GameState`.
2. Записать её в `_build_save_data()`.
3. Прочитать её в `_apply_save_data()`.
4. Для десктопа добавить запись/чтение в `_load_local_save()` и
   `_save_local_save()`.
5. Если поле влияет на UI, отправить существующий сигнал (`metal_changed`,
   `upgrades_changed` и т.п.) или добавить новый.
6. Проверить цикл: изменить → подождать сохранение → перезапустить → значение
   на месте.

### Новый звук

1. Добавить файл в `assets/` без пробелов и кириллицы в имени.
2. Создать `AudioStreamPlayer`/`AudioStreamPlayer2D`.
3. Указать `bus = AudioSettings.SFX_BUS` (или `MUSIC_BUS` для музыки).
4. Проверить, что кнопка «Звуки» его глушит, а пауза останавливает.

### Новая строка интерфейса

1. Добавить ключ в `en.csv`.
2. Использовать `tr("ключ")` в скрипте.
3. Переимпортировать CSV (Godot делает это при открытии проекта).
4. Проверить оба языка.

### Новая точка рекламы

1. Убедиться, что это естественная пауза, а не активный геймплей.
2. Вызвать `PlatformIntegration.gameplay_stopped()`.
3. Вызвать `PlatformIntegration.show_interstitial("placement")`.
4. Продолжить игру только после закрытия рекламы.
5. Проверить, что без поддержки рекламы игра не ломается.

## 6. Известные незакрытые пункты

- Карточка `laser` (`assets/resources/cards/laser.tres`) всё ещё не имеет
  эффекта. Её нужно либо реализовать, либо убрать из пула до релиза.
- Нет файла с подтверждением прав на музыку/спрайты/SFX. Нужен credits/LICENSE.
- Интеграцию нужно прогнать в реальном sandbox Яндекса: редактор и локальный
  экспорт не заменяют проверку платформы.
- Проверить поведение на мобильных браузерах (Яндекс Браузер, Chrome, Safari):
  полноэкранный режим, ориентация, долгое нажатие, контекстное меню.
- Проверить, что все ресурсы укладываются в лимит архива после финальной
  полировки.

## 7. Полезные команды

```bash
# Проверка импорта и парсинга скриптов
godot --headless --editor --quit

# Быстрый запуск игры без окна
godot --headless --path . --quit-after 120

# Интеграционный тест рогалика
ROCKET_TEST_NODEATH=1 godot --headless --path . res://test_roguelike.tscn

# Пробный Web-экспорт в отдельную папку
godot --headless --path . --export-release "Web" /tmp/closed-space-web/index.html
```
